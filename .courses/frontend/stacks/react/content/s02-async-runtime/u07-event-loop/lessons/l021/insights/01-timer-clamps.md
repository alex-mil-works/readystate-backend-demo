# setTimeout не обещает точную задержку

`setTimeout(fn, ms)` ставит **task** не раньше чем через `ms`. Пока стек занят или впереди другие задачи, колбэк опоздает.

В браузере есть нижние пороги: вложенные таймеры (несколько уровней подряд) зажимаются примерно до 4 мс, а фоновая вкладка может уводить таймеры на секунды. `setTimeout(fn, 0)` значит «следующая task», не «следующая строка».

`setInterval` не догоняет пропущенные тики пачкой, если колбэк сам длится дольше интервала. Он легко накладывает работу, если вы не смотрите, что предыдущий вызов ещё не закончился.

Коротко: _таймер планирует задачу, а не отмеряет время на стене_.
