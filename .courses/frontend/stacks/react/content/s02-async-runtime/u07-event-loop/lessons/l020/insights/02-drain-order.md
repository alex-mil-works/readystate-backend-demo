# Сначала все микрозадачи

После текущей задачи цикл такой:

1. Выполнить task до пустого стека.
2. **Опустошить очередь микрозадач**, включая те, что добавились по ходу.
3. Браузер может отрисовать кадр.
4. Взять следующую task.

Поэтому `Promise.then` почти всегда раньше `setTimeout(fn, 0)`. Ноль в таймере не значит «сразу после этой строки».

Если микрозадачи бесконечно ставят новые микрозадачи, очередь не отдаёт управление — кадр и клики ждут. Это уже не параллельность, а голодание event loop.
