# Свежий литерал строже

Тот же объект, записанный прямо в вызов, проверяется на лишние поля. Иначе опечатка `z` вместо нужного ключа прошла бы молча.

```ts
draw({ x: 1, y: 2, z: 9 }); // ошибка excess property
const dot = { x: 1, y: 2, z: 9 };
draw(dot); // допустимо
```

Это не защита от лишних полей в runtime. Переменная уже имеет свой тип, и лишнее поле просто не читают.

Коротко: _excess check ловит опечатку в литерале, не чужие поля у переменной_.
